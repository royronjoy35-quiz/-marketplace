# DR Marketplace Bot — Phase 1

Flat Go project: all `.go` files live in the repository root. No source subfolders.

## Files
- `main.go` — startup, HTTP server, graceful shutdown
- `config.go` — environment configuration and validation
- `handlers.go` — Telegram webhook, basic commands, user registration
- `telegram.go` — Telegram Bot API client and webhook setup
- `database.go` — MongoDB Atlas connection
- `models.go` — core data models
- `users.go` — user persistence
- `marketplace.go` — reserved for Phase 2 marketplace services
- `payments.go` — reserved for Telegram Stars payment implementation
- `wallet.go` — reserved for secure BEP-20 withdrawal implementation
- `admin.go` — admin access helper and future admin workflows
- `health.go` — `/health` and `/health/ready`
- `go.mod` — Go module dependencies

## Local run
1. Copy `.env.example` to `.env` and fill in real values.
2. Export those variables in your terminal (the app does not automatically load `.env`).
3. Run:
   ```bash
   go mod tidy
   go run .
   ```

## Render
Create a Web Service connected to this GitHub repository.

- Runtime: Go
- Build Command: `go mod tidy && go build -o bin/server .`
- Start Command: `./bin/server`
- Health Check Path: `/health`

Set these Render environment variables:
- `BOT_TOKEN`
- `BOT_USERNAME=dr_marketplace_bot`
- `TELEGRAM_WEBHOOK_SECRET` (at least 32 random characters)
- `PUBLIC_BASE_URL` (your public Render HTTPS URL)
- `MONGODB_URI`
- `DATABASE_NAME=dr_marketplace`
- `ADMIN_IDS` (optional, comma-separated numeric Telegram IDs)

Render supplies `PORT`; the server binds to `0.0.0.0:$PORT`. On startup, the app registers the Telegram webhook at `PUBLIC_BASE_URL + WEBHOOK_PATH`.

## UptimeRobot
Monitor `https://YOUR-SERVICE.onrender.com/health` with HTTP 200 expected. `/health/ready` also checks MongoDB.

## GitHub
Upload the contents of this folder directly to the repository root. Do not upload `.env`, tokens, database credentials, webhook secrets, wallet keys, or seed phrases.

## Phase 1 scope
Implemented: HTTP server, Telegram webhook registration and secret validation, MongoDB connection, user upsert, `/start`, `/help`, `/status`, health endpoints, structured logs, and graceful shutdown.

Scaffold only: marketplace, Stars payments, BEP-20 withdrawals, and admin workflows. Real payments/payouts are not enabled. Before production financial workflows, add durable webhook processing, update deduplication, retries, ledger accounting, idempotent payout execution, and isolated transaction signing.

`go.sum` is generated by `go mod tidy` using the resolved dependency checksums. It is intentionally not hand-written or populated with fabricated checksums.
